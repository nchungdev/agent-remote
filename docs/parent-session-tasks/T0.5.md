# T0.5 — Xác minh harness theo phiên bản (M)

Trước khi chốt D6 và API lõi, lập ma trận từ tài liệu gốc, source adapter Agent Remote và fixture của đúng bản CLI. Gắn từng khả năng với một trong ba trạng thái: có tài liệu, đã tái hiện, chưa xác minh. Dùng T0.4 cho phép đo tốn quota.
- **Claude Code.** Đối chiếu vòng lặp thu thập → thao tác → kiểm tra, resume/fork và compaction với adapter hiện chạy `claude -p` + `--resume`. Xác minh lifecycle khi chờ quyền, interrupt, lưu lịch sử, thay model và tác động của project settings/hooks. [Loop](https://code.claude.com/docs/en/how-claude-code-works) · [Sessions](https://code.claude.com/docs/en/agent-sdk/sessions)
- **Codex.** Đối chiếu giao diện exec/resume đang dùng với App Server thread/turn/item, resume, interrupt, compact, approvals và telemetry. Chọn transport sau khi kiểm tra schema của binary mục tiêu và chi phí tích hợp. [App Server](https://developers.openai.com/codex/app-server/)
- **Antigravity.** So sánh print + `--conversation` đang dùng với headless stream stdin nhiều lượt. Kiểm tra scope workspace, cách hủy, chế độ chỉ đọc và nguồn context/quota thực sự có trên đường tích hợp. Headless stream nhiều lượt có usage tích lũy theo tài liệu; adapter phải tính delta theo native session và xử lý khi counter reset. [Headless](https://antigravity.google/docs/cli/headless/) · [Context](https://antigravity.google/docs/cli/commands/context/) · [Status line](https://antigravity.google/docs/cli/statusline)
**Xong khi:** có fixture cho hai lượt cùng process, resume sau restart, compact hoặc trạng thái không quan sát được, hủy khi đang chạy tool, approval, và usage/quota thiếu dữ liệu. Kiểm thử sandbox bằng thao tác ghi thực trên repo test. Đo cùng task theo resume và session mới, gồm token gửi, cache, độ trễ và độ đúng bước tiếp theo. D6 yêu cầu phiên logic có thể tiếp tục; việc giữ process sống lâu do adapter quyết định từ kết quả đo.
