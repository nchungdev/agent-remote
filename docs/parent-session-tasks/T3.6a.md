# T3.6a — Tạo và phục hồi worktree (M)

Sau khi T2.4a và pilot A → B → A đạt, thêm thao tác tạo worktree do server quản lý. App gửi repo ID đã được cấp quyền và commit đã chọn từ branch nguồn; server xác minh quyền, resolve và pin SHA, cấp checkout ID và chọn branch `codex/<task-id>` cùng đích dưới managed root. Gọi `git worktree add -b <branch> <path> <base-sha>` qua `exec.CommandContext` với danh sách đối số. Kiểm tra lại root, branch và HEAD thực tế trước khi báo **Sẵn sàng**. Ghi operation ID và dữ liệu dự kiến trước khi gọi Git; retry/restart đối chiếu với Git, nối record nếu đã tạo đúng và báo **Cần xác minh** nếu trạng thái mơ hồ.
**Xong khi:** retry không tạo thêm checkout, worktree mới từ commit đã chọn không thấy staged/unstaged/untracked của checkout nguồn, và một số ref/dữ liệu Git dùng chung được tính đến trong kiểm tra.
**Test hợp đồng:** chạy Claude/Codex/agy trên checkout hiện tại và worktree riêng theo capability đã xác minh; kiểm tra working directory thực tế, native resume đúng checkout, và từ chối resume khi project native trỏ về checkout khác. Đăng ký một fake engine mới rồi chạy cùng luồng tạo phiên, tạo worktree, gửi và chuyển writer mà không chỉnh workspace service, protocol handler hay UI.
